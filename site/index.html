Volens Field Manual

A bot that watches wallets which have made money, buys what they buy, and sells on rules you set. Everything is driven from Telegram buttons. This is how to run it without hurting yourself.

01What it actually does

The whole idea in four sentences.

Volens listens to every Solana transaction on the exchanges where new tokens trade — tens of thousands a minute. It keeps a list of 1,117 tracked wallets that have historically traded well, of which about 780 are in the active cohort.

When several of those wallets independently buy the same token inside a ten-minute window, that's a signal. If the signal clears your thresholds and every safety check passes, the bot buys — then watches the position and sells it on a ladder you define.

It does not predict anything. It follows people, quickly.

02The one control that matters

Learn this before anything else.

HALT stops all trading instantly. Not the next cycle — immediately, and it's checked before every single buy and every single sell.

Telegram
/halt — stop everything /resume — start again

It writes a file to disk, which means it survives a restart. If the machine reboots while halted, it comes back halted. That's deliberate: the safe state has to be the sticky one.

If anything looks wrong

Hit /halt first and ask questions after. There is no cost to halting and no cost to resuming. Every other control on this page is a preference; this one is a brake.

04Buyers, and why the number is delicate

The single setting that decides how often anything happens at all.

"4 buyers" means four different tracked wallets bought the same token within ten minutes. Not four purchases — four separate wallets, arriving independently.

Because it's four-of-780, small changes swing the fire rate hard:

ThresholdEffect
2–3Fires often. More noise, more entries, more fees.
4–5Balanced. Several signals an hour on a busy day.
6+Rare. You will miss good tokens for being one wallet short.

That last row isn't hypothetical. At a threshold of 5, a token reached 4 buyers and stopped — then ran to 4.07×. Higher is not safer; it's just quieter.

05Selling: stops and targets

The half that protects you, and the half most people set up wrong.

🎚 Auto-sell · 🟢 On
🛑 STOPS — checked first -15% → sell 100% 🎯 TARGETS — lowest first +100% → sell 50% (50% left) +250% → sell 20% (30% left) +400% → sell 20% (10% left) +900% → sell 10% (nothing left) 📉 Trailing: off

Three rules govern the whole thing:

  • Stops are checked before targets. A position that gaps from +300% to −60% exits, rather than taking a target on the way past.
  • Amounts are shares of the original position, so they accumulate. The screen shows what's left after each rung so you don't have to do the arithmetic.
  • Targets fire lowest-first, once each.
The classic mistake

A ladder like −15% → 100% and +25% → 100% closes the entire position at +25%. Every rung above it — +250%, +400%, +900% — can never fire. The screen now says so outright when it detects this, but it's worth understanding rather than being told.

The trailing stop sells everything once the position falls a set percentage from its peak. It only activates after the position has been in profit, so it can't close a fresh entry on ordinary slippage.

06Volume mode

Optional. Makes the bot pickier, never looser.

Normally the buyer count alone decides. Turn volume mode on and a signal must also show real flow behind it:

📊 Volume mode · 🟢 on
🟢 On — tap to disable
💸 Smart SOL in · 2 SOL 📈 Token volume · 30 SOL
  • Smart SOL in — how much the tracked wallets themselves put in. Five wallets at 0.05 SOL each is a different signal from five at 5 SOL each, and a plain count can't tell them apart.
  • Token volume — total trading in that token over the same ten-minute window.

Either can be set to 0 to switch that half off. Smart money remains required — volume can only ever block a signal, never create one.

Use it as a measuring tool first

Turn volume mode on with both thresholds at 0. It then blocks nothing but logs the real numbers on every signal. After a day you'll know where to set them, instead of guessing.

07What runs before every buy

Seven checks. Any one of them refuses the trade.

CheckRefuses when
HALTYou've stopped the bot.
Rug blacklistThis token's liquidity was seen being pulled — ever, this session.
Mint authorityThe creator can still print more supply.
Freeze authorityThe creator can still freeze your account, trapping the position.
Token-2022The token has extensions that can change the rules under you.
Price impactYour own order would move the price more than the limit — the pool is too thin to exit.

All of them fail closed. If a check can't be read — the network is down, a price is missing — it refuses rather than assuming the best. A skipped trade costs nothing; a wrong one costs money.

08Reading the alerts

What lands in the group, and what each one means.

A buy

🟢 SMART BUY · Grizzl…8ppump 0.01 SOL confirmed 4fPt56PL…

The token is identified by a shortened mint address, not a name. Amount, then where the transaction ended up. Tap Positions for entry market cap, current market cap and live P&L — those live on the position screen, not in the alert.

A sell

🔴 AUTO-SELL · Grizzl…8ppump 100% · est 0.0198 SOL target +100% → sell 100% confirmed 2yh6iS2E…

The third line is the rung that fired, in the same words as the ladder screen. If it says stop -15%, the stop caught it.

Skipped, with a reason

⚪ Smart buy skipped · 297uf7…ivpump price impact 2720 bps exceeds 1000

This is the bot working, not failing. It's telling you the pool was too thin to get back out of.

The one worth watching for

🟠 Position stopped trading · E6Vhd3…ZZpump No fills observed, so it cannot be priced — or sold — right now. Auto-sell is holding rather than acting on a price it does not have.

Nothing is trading that token, so there is no honest price. The bot holds rather than acting on a number it does not have. This usually clears within seconds — one observed case lasted 33 seconds and then sold normally. If it persists, look at the token yourself and consider selling by hand from the position screen.

09What it costs to trade

Real numbers from a real session, because this surprises people.

Over 62 round trips in two hours, roughly 0.75 SOL of volume passed through a 0.03 SOL wallet — the money recycles each time you buy and sell.

Two things follow from this, and they're the most practically useful facts on this page.

Roughly half the cost is fixed. Network fees are the same whether you trade 0.01 SOL or 1 SOL. At 0.01 they're 1.4% of the trade; at 0.1 they're 0.14%; at 1 SOL, 0.014%.

So small trades are inefficient, not safe. At 0.01 SOL you're paying about 3.2% per round trip in friction. The signal has to beat that before anything else. Trading bigger doesn't reduce risk — but it does stop the costs from drowning the result.

10A safe first session

In order. The whole point is that step 6 is boring.

  1. Fund a dedicated wallet

    Never your main one. Enough that fees aren't most of the cost — around 1 SOL is a sensible floor.

  2. Back up the key somewhere else

    If the machine dies or the host suspends the box, an unexported key is simply gone.

  3. Set the limits before arming

    Size, trades/day, and the stop. Decide what a bad day looks like while you're calm.

  4. Set a stop you'd actually accept

    A ladder with no stop has no floor. −15% → 100% is a reasonable starting point.

  5. Resume, and watch the first trade land

    Buy alert, then sell alert. Confirm the exit reason matches what the token actually did.

  6. Then leave it alone

    Judge it over dozens of trades, not one. A single result tells you nothing either way.

11Honest limits

Things worth knowing before trusting it with size.

  • It follows, it doesn't predict. If the tracked wallets have a bad week, so does the bot.
  • Volume has no direction. A token collapsing prints enormous volume too. The wallet signal supplies the direction; volume only confirms.
  • Some tokens can't be sold at any price. If liquidity is pulled, no exit strategy helps. The stop can only fire while someone is still buying.
  • Speed is location. Running near the data source is worth more than any code change — the same bot is about 830ms faster per entry on a well-placed server than on home internet.
  • Only ever run one copy. Two instances sharing a wallet will double-trade every signal.
The real risk

This is unattended software spending real money on brand-new tokens, most of which go to zero. The guards reduce a specific set of known failures. They do not make it safe, and nothing here should be money you need.
